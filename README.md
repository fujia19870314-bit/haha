# AI 哀伤引导日记 - 后端

基于 TDD 开发的心理健康支持应用后端，使用通义千问大模型提供温和的哀伤陪伴。

## 已完成的 MVP 核心模块

### 1. LLM 抽象层 (`backend/types/llm.ts`, `backend/lib/qwen-provider.ts`)

**接口定义：**
- `LLMProvider` 接口定义了标准的 LLM 提供商契约
- 支持多种 LLM 提供商的无缝切换

**通义千问实现：**
- 完整的 API 调用封装
- 支持自定义温度、最大 token
- 统一的响应格式
- 连接健康检查

### 2. 危机检测模块 (`backend/lib/crisis-detector.ts`)

**功能特性：**
- 三级风险等级：low / medium / high / critical
- 关键词匹配：覆盖自杀、自残、死亡意愿等危险信号
- 语义分数计算：基于关键词强度和文本长度
- 危机热线支持

**检测能力：**
- 明确的自杀计划或方法
- 强烈的死亡意愿表达
- 自我伤害意图
- 绝望情绪表达

### 3. 系统提示词模块 (`backend/lib/system-prompt.ts`)

**核心原则：**
- 不评判、不说教、不强迫"积极"
- 安静地见证，承认痛苦的合理性
- 保持在场，而不是试图"解决"悲伤

**三条禁令（严格执行）：**
1. ❌ 禁止使用"感谢分享"及类似表达
2. ❌ 禁止使用"我懂你的感受"及类似表达
3. ❌ 禁止使用"作为人工智能"及类似身份声明

**响应验证：**
- `validateResponse()` 函数自动检查 AI 响应是否符合规范

## 数据库 Schema

核心数据表：
- `users` - 用户信息（含与逝者关系字段）
- `diaries` - 日记内容
- `ai_responses` - AI 响应记录
- `crisis_logs` - 危机检测日志（只存结果，不存全文，符合隐私合规）
- `subscriptions` - 订阅信息
- `payment_orders` - 支付订单

详细 schema 见 `docs/schema.sql`
